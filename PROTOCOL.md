# axsh protocol

## Framing

axsh works over any protocol that can stream bytes. On top of this it uses HDLC
to create "packets" inside this byte stream.

## Keys and signers

`ConnSign` is the root of trust of a connection. It signs the handshakes, and is
quantum resistant. This key is long lived.

`PacketSign` is not quantum resistant, but is ephemeral and single use for the
connection. Its signatures are MUCH smaller. If a quantum computer will become
able to break this key before the connection ends, then this algorithm needs to
be changed.

Client and server each have a `ConnSign` and `PacketSign` keys, generated by
each locally.

## Handshake

There are two handshake paths:

1. Client already knows the server `ConnSign` public key from `known_hosts`.
2. Client only knows the SHA-256 digest from `ServerHello`, and requests the
   full key from the server.

The full client `ConnSign` public key is never sent on the wire. The server
learns it from `authorized_keys`.

### Known-hosts path

```text
client                                                  server
  |                                                       |
  |<-- ServerHello ---------------------------------------|
  |    unsigned - contents later signed in ServerComplete |
  |    fields:                                            |
  |      server_unique                                    |
  |      sha256(server ConnSign pubkey)                   |
  |      server PacketSign pubkey                         |
  |                                                       |
  |    client checks:                                     |
  |      sha256(known_hosts pubkey) == advertised digest  |
  |                                                       |
  |-- ClientHello --------------------------------------->|
  |   signed by client ConnSign over:                     |
  |     server_unique || client_hello_body                |
  |   wire body fields:                                   |
  |     client_unique                                     |
  |     sha256(client ConnSign pubkey)                    |
  |     client PacketSign pubkey                          |
  |                                                       |
  |    server checks:                                     |
  |      sha256(client pubkey from authorized_keys)       |
  |        == advertised digest                           |
  |      ConnSign signature verifies over                 |
  |        server_unique || client_hello_body             |
  |                                                       |
  |<-- ServerComplete ------------------------------------|
  |    unsigned packet carrying detached ConnSign sig     |
  |    signature covers:                                  |
  |      raw ServerHello bytes || raw ClientHello bytes   |
  |                                                       |
  |    client verifies transcript signature               |
  |                                                       |
  |==== handshake complete ===============================|
  |                                                       |
  |<=> Payload packets in both directions                 |
  |    signed with PacketSign                             |
  |    implicit per-direction counters stop replay/order  |
  |                                                       |
```

### Unknown-server-key path

```text
client                                                  server
  |                                                       |
  |<-- ServerHello ---------------------------------------|
  |                                                       |
  |-- RequestServerPubkey ------------------------------->|
  |    unsigned                                           |
  |                                                       |
  |<-- ServerPubkey --------------------------------------|
  |    unsigned                                           |
  |    The server's ability to sign using the key proves  |
  |    it.                                                |
  |                                                       |
  |    fields:                                            |
  |      full server ConnSign pubkey                      |
  |                                                       |
  |    client checks:                                     |
  |      sha256(received pubkey) == digest from           |
  |        ServerHello                                    |
  |      user / known_hosts policy accepts the key        |
  |                                                       |
  |-- ClientHello --------------------------------------->|
  |<-- ServerComplete ------------------------------------|
  |                                                       |
```

### Why the server nonce is not in `ClientHello`

`ClientHello` does not serialize `server_unique`. This saves 8 bytes on the
wire, but the nonce is still covered by the client's `ConnSign` signature, so
an attacker cannot replay a `ClientHello` from one server challenge into a
different one.
